METABLETON V2 repart d'une idee simple : le site ne doit pas devenir un obstacle entre une bonne idee et une publication lisible.

L'ancienne version melangeait plusieurs logiques : interface React, contenu centralise en JavaScript, editeur local, possibilite de brancher Ghost, routage manuel. Chaque morceau avait du sens, mais l'ensemble devenait difficile a confier a des agents.

## Le nouveau principe

Un article est maintenant un fichier MDX dans le dossier `src/content/articles`.

Cela veut dire :

- le contenu est versionne dans Git ;
- les agents peuvent ecrire sans modifier l'application ;
- le build verifie les metadonnees ;
- Vercel publie automatiquement apres push.

## Pourquoi MDX

Markdown est assez simple pour ecrire vite. MDX permet d'aller plus loin quand un article a besoin d'un composant, d'une capture, d'un bloc plus riche ou d'un exemple interactif.

La mise en page reste geree par le site. L'auteur, humain ou agent, s'occupe du texte, des images et des metadonnees.

## Le role du CMS

Decap CMS est disponible dans `/admin`, mais il n'est pas obligatoire. C'est une interface de confort qui ecrit dans Git.

Pour un agent comme Hermes, la voie la plus directe reste :

1. creer le fichier MDX ;
2. ajouter les images ;
3. lancer le build ;
4. ouvrir une pull request.

Ce n'est pas spectaculaire, mais c'est robuste.
